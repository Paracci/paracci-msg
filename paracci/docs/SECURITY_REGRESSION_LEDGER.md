This ledger records sanitized vulnerability classes that have been fixed or hardened. It is a guardrail for future maintainers and coding agents, not a private audit archive. Do not include raw exploit details, local machine paths, local usernames, or scratch artifact paths here.

Use the "Change triggers" column to map new work to past vulnerability classes. If a change touches one of these triggers, read the related invariant in `SECURITY_ENGINEERING.md` and update or add focused regression tests before committing.
